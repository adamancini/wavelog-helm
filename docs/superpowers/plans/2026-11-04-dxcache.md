# DXCache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional, in-cluster DXCache (upstream DXClusterAPI) in the wavelog chart that merges spots from several telnet DX cluster nodes and is wired into Wavelog automatically.

**Architecture:** `dxcache.enabled` adds a single-replica Deployment (Recreate), a ClusterIP Service, a PVC and a Secret holding the `CLUSTERS` JSON. An init container waits until Wavelog's `/index.php/api/lookup` answers with the chart-generated key. Wavelog's bootstrap init container seeds that key (read-only) and upserts `options.dxcache_url`. When the feature is disabled, it clears the URL only if the chart owns it.

**Tech Stack:** Helm 3/4 templates, helm-unittest v1.0.3, PHP 8 (`bootstrap.php`), bash e2e on kind/Colima, `ghcr.io/int2001/dxclusterapi:1.5.8` (Bun).

**Spec:** `docs/superpowers/specs/2026-11-04-dxcache-design.md`. Read it first. This plan only records decisions the spec leaves open.

## Review Focus

1. **`config.existingSecret` set together with `dxcache.enabled`.** The generated `dxcache-api-key` must still come from `<fullname>-app`, never from the user's Secret. The `<fullname>-app` Secret must render even when both `needKey` and `needAdmin` are false (Task 3 test).
2. **A cluster password Secret with a trailing newline**, the usual `kubectl create secret --from-file` artifact. The password goes into CLUSTERS trimmed (Task 2 test).
3. **`oauth2Proxy.enabled` with `service.port` changed from 80.** `WAVELOG_URL` uses `.Values.service.port`, never a hard-coded 80 or 4180 (Task 4 test).
4. **The operator set `dxcache_url` by hand to some other URL, then enabled and later disabled the chart's DXCache.** Disable must clear only a URL starting with the chart prefix `http://<fullname>-dxcache.` (Task 5 unit test and e2e).
5. **`fullnameOverride` / a release name that changes the fullname.** Every DXCache resource name, the Service DNS name in `WL_DXCACHE_URL`, and the NetworkPolicy selector derive from the `wavelog.dxcache.fullname` helper (Task 4 test with `fullnameOverride: logbook`).

### Task 5: Bootstrap `configure_dxcache`

**Files:**
- Modify: `charts/wavelog/files/bootstrap.php`
- Test: `test/e2e/bootstrap_unit.php`

**Interfaces:**
- Consumes: env `WL_DXCACHE_URL`, `WL_DXCACHE_URL_PREFIX`, `WL_DXCACHE_API_KEY`, `WL_ADMIN_USERNAME`.
- Produces:
  - `function dxcache_url_owned(string $current, string $prefix): bool`: true iff `$prefix !== ''` and `$current` starts with `$prefix`.
  - `function upsert_api_key(mysqli $db, string $key, string $rights, string $desc, int $uid): void`: extracted from `seed_api_keys` (its exists/update/insert body). `seed_api_keys` must call it, so the logic isn't duplicated.
  - `function admin_user_id(mysqli $db, string $user): int`: extracted the same way, and it fails like today when the user isn't found.
  - `function configure_dxcache(mysqli $db): void`, called in `main()` right after `seed_api_keys($db)`.

Behaviour of `configure_dxcache`:

- **`WL_DXCACHE_URL` non-empty:**
  - `trim` the key; `fail('dxcache: WL_DXCACHE_API_KEY is empty')` if it's empty.
  - `upsert_api_key($db, $key, 'r', 'DXCache (managed by chart)', admin_user_id($db, env('WL_ADMIN_USERNAME')))`.
  - Upsert the option with `INSERT INTO options (option_name, option_value, autoload) VALUES ('dxcache_url', ?, 'yes') ON DUPLICATE KEY UPDATE option_value = VALUES(option_value)`, using the `option_name` unique key.
  - `info('dxcache wired: ' . $url)`.
- **Empty:** read the current `dxcache_url`. If `dxcache_url_owned($current, env('WL_DXCACHE_URL_PREFIX'))`, run `UPDATE options SET option_value = '' WHERE option_name = 'dxcache_url'` and `info('dxcache_url cleared')`. Otherwise do nothing.

**Interfaces:**
- Consumes: everything above. Wavelog spot endpoint: `GET <url>/index.php/dxcluster/spots/All` (session-authenticated; method `Dxcluster::spots($band, $age, $de, $mode)`).

Fake node (`fake-dxnode.yaml`): two Deployments plus Services, `fake-dx-a` and `fake-dx-b`, using `busybox:1.37`. Each runs a shell loop under `nc -lk -p 7300` (or `nc -ll` if the busybox build needs it; verify) that:
1. prints `login: `;
2. reads one line;
3. prints a welcome line;
4. every 20 s prints spot lines matching DXCache's `deline` regex (`lib/dxcluster.js`), using the current UTC `HHMM`. Pin this format:
   `DX de N0CALL-1:   14025.0  K1ABC        CW 599                         1234Z`

Node A emits `K1ABC` on 14025.0 and `JA1XYZ` on 21074.0. Node B emits `K1ABC` on 14025.0 (spotter `N0CALL-2`) and `VK2ABC` on 7010.0.

`values-dxcache.yaml`: `values-common.yaml` style, admin callsign `N0CALL`, `dxcache.enabled: true`, `callsign: N0CALL-7`, `clusters` = both fake Services on 7300, `pota.enabled: false`, `sota.enabled: false`, `persistence.size: 1Gi`.

`ci/dxcache-values.yaml`: `baseUrl`, declarative, `dxcache.enabled: true`, `callsign: N0CALL-7`, one cluster `{host: dxc.example.org, port: 7300}`.

`dxcache.sh` assertions, in order:
1. Apply the fake nodes, `e2e_install -f values-dxcache.yaml`, and wait for the `<fullname>-dxcache` rollout (timeout 300 s).
2. `assert_eq "http://$E2E_FULLNAME-dxcache.$E2E_NS.svc:3000"` against `e2e_sql "SELECT option_value FROM options WHERE option_name='dxcache_url'"`.
3. `assert_eq 1` on the count of `api` rows with `description='DXCache (managed by chart)' AND rights='r'`.
4. Poll (up to 120 s) after `e2e_login` until `/index.php/dxcluster/spots/All` returns JSON where `jq '[.[] | select(.spotted=="K1ABC")] | length'` is `1` (merged across nodes) and `JA1XYZ` and `VK2ABC` are both present.
